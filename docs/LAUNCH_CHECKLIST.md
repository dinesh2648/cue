# Launch Checklist — Cue for Sales (Sales-first rollout)

This rollout ships **only the Sales pack** (`ENABLED_PACKS=sales`). Other verticals exist
in the codebase but are not exposed. Work top-to-bottom for go-live.

## 0. Decide the launch tier

| Tier | What's on | Good for |
|---|---|---|
| **Pilot (zero-cred)** | Simulated meetings, seeded CRM/docs, offline answers, demo OAuth consent | Internal demo / design partner, day one |
| **Connected pilot** | + Anthropic (real Claude) + a few real connectors | A real sales team on real data |
| **Production** | + Google sign-in + Postgres + Recall.ai + HTTPS | GA rollout |

You can launch the **Pilot** today with no credentials.

## 1. Required for production (security)

- [ ] `TOKEN_ENCRYPTION_KEY` — strong random secret (encrypts every user's OAuth tokens). **Required.**
- [ ] `SESSION_SECRET` — strong random secret (signs session JWTs). **Required when Google login is on.**
      The server **refuses to start** if Google login is enabled and both secrets are unset
      (it would otherwise fall back to a public dev key — see `_check_production_secrets`).
- [ ] `RECALL_WEBHOOK_SECRET` — strong random secret authenticating the inbound transcript
      webhook (the bot's callback URL carries a per-meeting HMAC). Falls back to `SESSION_SECRET`.
- [ ] `DATABASE_URL` — Postgres (`postgresql+psycopg://…`); the bundled image includes the driver.
- [ ] Serve everything over **HTTPS** (OAuth redirect URIs require it).
- [ ] `CORS_ORIGINS`, `APP_BASE_URL`, `FRONTEND_URL` set to your real domains.
      Use explicit origins — a wildcard `*` forces credentials off (the server won't emit
      credentialed CORS with a wildcard).
- [ ] `ENABLED_PACKS=sales` (default) — keeps the launch scoped to Sales.
- [ ] Confirm `RECALL_TREAT_ALL_AS_CUSTOMER` is **unset** (solo-test aid only — mislabels the rep).

## 2. Turn on real Claude (recommended)

- [ ] `ANTHROPIC_API_KEY` set → answers + summaries generated by Claude (engine auto-selects `messages_mcp`).
- [ ] Pick `ANTHROPIC_MODEL` (default `claude-sonnet-4-6`).

## 3. Auth (Google sign-in, production)

- [ ] Create a Google OAuth client → set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and
  `SESSION_SECRET` (signs session JWTs; falls back to `TOKEN_ENCRYPTION_KEY`) on the backend.
  Register the sign-in redirect URI `{APP_BASE_URL}/api/auth/google/callback`. No frontend
  build arg is needed — the frontend reads `/api/auth/config` to show "Continue with Google".
- [ ] Without Google creds it runs single-user DEV mode — fine for a closed pilot, not for GA.

## 4. Connectors (each rep connects their own)

For one-click OAuth on a provider, register your app once and set its client id/secret;
redirect URI: `{APP_BASE_URL}/api/connectors/{provider}/callback`.

- [ ] HubSpot — `HUBSPOT_CLIENT_ID` / `HUBSPOT_CLIENT_SECRET`
- [ ] Google (Drive/Gmail/Calendar) — `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`
- [ ] Notion — `NOTION_CLIENT_ID` / `NOTION_CLIENT_SECRET`
- [ ] (Optional) self-hosted MCP URLs for Drive/Gmail/Calendar/LinkedIn

> Until a provider's client id is set, **Connect** uses the built-in demo consent screen —
> good for the pilot; swap to real OAuth before GA.

## 5. Meeting capture

- [ ] `RECALL_API_KEY` + `RECALL_REGION` → real Google Meet / Zoom / Teams bots.
- [ ] Expose `{APP_BASE_URL}/api/webhooks/recall` publicly (Recall calls it). The endpoint is
      HMAC-authenticated per meeting — requests without the issued `token` are rejected (403),
      so it's safe to expose. Sign-off needs a publicly reachable, stable HTTPS URL.
- [ ] Without it, the built-in simulator is the capture source (fine for pilot/demo).

## 6. Deploy

```bash
docker compose up --build           # backend :8000 + frontend :3000 (SQLite, pilot)
# production: set env above; use Postgres via --profile full, or your managed DB
```
Or: backend `uvicorn app.main:app --host 0.0.0.0 --port 8000`; frontend `npm ci && npm run build && npm start` (or Vercel). Set `NEXT_PUBLIC_API_URL` to the public backend URL.

> **Frontend Node version:** build with **Node 20–24** (LTS; pinned in `frontend/.nvmrc` and
> `package.json` `engines`). Node 25+ trips a native package-config reader bug in the Next.js
> toolchain and fails the build. Run `nvm use` in `frontend/` before `npm ci`.

- [ ] **Postgres schema:** run `alembic upgrade head` (SQLite auto-creates tables; Postgres uses migrations).
- [ ] **Billing (optional):** set `STRIPE_SECRET_KEY`, `STRIPE_PRICE_PRO/ENTERPRISE`, `STRIPE_WEBHOOK_SECRET`; register the webhook `{APP_BASE_URL}/api/webhooks/stripe`. Without it, plans work in dev mode (upgrades apply directly). Free plan: 5 meetings/mo, 2 connectors.

## 7. Smoke test (post-deploy)

- [ ] `GET /health` → ok; `GET /api/packs` → **only `sales`**.
- [ ] Start a demo meeting → live transcript + grounded suggestions appear (<5s).
- [ ] End meeting → summary renders; **Approvals** panel lists proposed CRM writes.
- [ ] Approve → CRM note/tasks/email written; reject → nothing written.
- [ ] Connect a tool on the Connections page → returns connected.
- [ ] **Tenancy/authz spot-check:** unauthenticated `GET /api/crm/objects`, `/api/meetings`,
      `/api/meetings/{id}`, `/api/meetings/{id}/actions` → **401**; `POST /api/webhooks/recall`
      without the issued `token` → **403**. A user from one org must never see another org's
      meetings or CRM rows (all CRM data is `org_id`-scoped).
- [ ] (Repo) `pytest -q` → 8/8; the full E2E script → all green.

## 8. Go-live & rollback

- [ ] Monitor `/metrics` (latency, SLA compliance) and `audit_logs`.
- [ ] Rollback = redeploy the previous image tag; data is in Postgres (and the token vault).
- [ ] Adding a vertical later: implement the pack, then add its key to `ENABLED_PACKS`.

## 9. Residual / accepted risks (reviewed)

- **`/metrics` SLA compliance** reflects the *deep agentic* tier (web/MCP research is
  inherently multi-second). The SLA-critical path is the **fast tier**, which emits an
  instant grounded card; the deep answer streams in after. Don't read low `sla_compliance_pct`
  as a regression — it's the research path. Tune `RESPONSE_SLA_SECONDS` to your bar.
- **postcss advisory (GHSA-qx2v-qp2m-jg93, moderate)** is transitive inside Next.js 15.5.19's
  bundled toolchain; it's a build-time CSS-stringify issue, not runtime-exploitable here. The
  only "fix" (`npm audit fix --force`) swaps Next to a canary and breaks the build — **not done
  on purpose.** Re-evaluate on the next Next.js minor bump.
- **First user in a new email domain becomes the org owner** (tenant bootstrap). Gated by
  Google `email_verified`, so the person must control that mailbox. Acceptable for self-serve;
  if you need invite-only tenants, disable open sign-up and provision owners manually.
- **Rate limiter is per-instance, in-memory** (fixed-window). Fine for a single backend; for
  multi-instance, move it to Redis (`REDIS_URL` is already plumbed).

**Launching now:** the Sales pack only. Everything above is wired and verified
(E2E + 8/8 unit + production build). This session additionally hardened: per-meeting/CRM/action
tenancy (IDOR closed, CRM `org_id`-scoped), HMAC-authenticated Recall webhook, fail-fast on
insecure prod secrets, `email_verified` enforcement, request length-validation, and a Node
20–24 build pin. Clerk was fully removed (Google sign-in only).
