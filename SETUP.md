# Cue — Complete Setup Guide

Everything needed to run, configure, and go live. **Cue runs with zero credentials**
(simulated meetings, seeded data, offline answers) — add keys below to turn on real Claude,
SSO, billing, connectors, and meeting bots.

## 1. Prerequisites

- **Easiest (recommended):** Docker Engine + Docker Compose v2.
- **Manual:** Python 3.11+ and Node.js 20+.

Nothing else is required to start — no API keys, no database.

---

## 2. Run it (three ways)

### A) Docker (recommended)
```bash
cp .env.example .env          # optional: add keys; blank = zero-cred pilot
./scripts/setup.sh            # build + start + health-check + migrate
```
→ Frontend http://localhost:3000 · API http://localhost:8000 (docs at `/docs`).

### B) Manual (local dev)
```bash
# Terminal 1 — backend
cd backend && ./run.sh                       # venv + deps + seed + uvicorn :8000
# (config: backend/.env — copy from backend/.env.example)

# Terminal 2 — frontend
cd frontend && npm install && npm run dev     # :3000
# (config: frontend/.env.local — NEXT_PUBLIC_API_URL, NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY)
```

### C) Open and use
Visit http://localhost:3000 → **Start demo meeting** to watch the copilot work a simulated
call end to end. **Connections** to connect tools, **Settings** for plan/usage/team.

> **Two config files:** Docker reads the **root `.env`** (it feeds both services).
> Manual run reads **`backend/.env`** + **`frontend/.env.local`**. Same variable names.

## 4. Claude (the AI)

1. Get an API key from the Anthropic Console.
2. Set `ANTHROPIC_API_KEY` (and optionally `ANTHROPIC_MODEL`).

Answers + summaries are now generated by Claude over the connected tools (engine
auto-selects `messages_mcp`). With no key, the deterministic offline composer is used so
the app still works. (Local dev tip: if you're signed into the `claude` CLI, set
`AGENT_ENGINE=agent_sdk` to run Claude locally with no API key.)

## 5. Auth / SSO (Clerk)

Without Clerk, Cue runs in **DEV mode**: a single seeded user, no login — fine for a closed
pilot. For real multi-user SSO:

1. Create a Clerk application.
2. Backend: `CLERK_SECRET_KEY`, `CLERK_PUBLISHABLE_KEY`, `CLERK_ISSUER`
   (e.g. `https://your-app.clerk.accounts.dev`).
3. Frontend: `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` (Docker: passed automatically from
   `CLERK_PUBLISHABLE_KEY`).
4. Set `TOKEN_ENCRYPTION_KEY` to a strong secret.

Each signed-in user gets a workspace (Organization); roles are owner/admin/member.

## 6. Connectors

**Each employee connects their own tools** — the copilot only ever reads what *they* can
access (per-user tokens, encrypted, used only on their behalf). Connect from the
**Connections** page. Three ways, in priority order:

1. **OAuth click-through (default):** click **Connect [Provider]** → the provider's consent
   page → approve → connected. Requires the provider's OAuth app to be registered (below).
2. **Demo consent (zero setup):** if no OAuth app is registered, **Connect** opens a built-in
   consent screen that mirrors the real flow — great for pilots/demos.
3. **Bring your own token ("use a token"):** paste a personal access token + (optionally) an
   MCP server URL. Works for any provider/MCP.

### Registering a provider OAuth app (for the real click-through)

Set the client id/secret env vars and add this **redirect URI** in the provider's app:

```
{APP_BASE_URL}/api/connectors/{provider}/callback
```

| Provider | `provider` (path) | Env vars | Notes |
|---|---|---|---|
| HubSpot | `hubspot` | `HUBSPOT_CLIENT_ID` / `HUBSPOT_CLIENT_SECRET` | Scopes: CRM read (contacts/companies/deals) + tickets. Hosted MCP default set. |
| Google Drive | `google_drive` | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | drive.readonly |
| Gmail | `gmail` | (shares Google app) | gmail.readonly |
| Google Calendar | `google_calendar` | (shares Google app) | calendar.readonly |
| Notion | `notion` | `NOTION_CLIENT_ID` / `NOTION_CLIENT_SECRET` | Hosted MCP default set. |
| LinkedIn | `linkedin` | `LINKEDIN_CLIENT_ID` / `LINKEDIN_CLIENT_SECRET` | Basic profile only via standard OAuth; richer data needs a partner/provider MCP. |

> **Google:** the three Google connectors share **one** Google OAuth app — register **all
> three** redirect URIs (`…/google_drive/callback`, `…/gmail/callback`,
> `…/google_calendar/callback`) and add the matching scopes. Redirect URIs must be HTTPS in
> production.

### MCP servers
HubSpot and Notion have hosted MCP servers (defaults pre-set). For Google/LinkedIn (no
official hosted MCP), point `GOOGLE_DRIVE_MCP_URL` / `GMAIL_MCP_URL` /
`GOOGLE_CALENDAR_MCP_URL` / `LINKEDIN_MCP_URL` at a self-hosted or provider MCP. Until an MCP
URL exists, a connection still stores the token (ready when you add a URL).

### Adding a new connector
Add one entry to `backend/app/connectors/registry.py` (OAuth endpoints + scopes + MCP URL).
No other changes needed.

## 7. Billing (Stripe) + plans

Plans (config-driven in `backend/app/billing/plans.py`):

| Plan | Meetings/mo | Connectors | Notable |
|---|---|---|---|
| **Free** | 5 | 2 | — |
| **Pro** ($49/mo default) | unlimited | all | Recall.ai bots |
| **Enterprise** (custom) | unlimited | all | + SSO, custom limits |

Limits are **enforced** (over-limit returns HTTP 402 with an upgrade prompt). Usage is
metered per organization.

**Without Stripe:** upgrades on the Settings page apply directly (dev mode) so you can test
limits. **To charge for real:**
1. `STRIPE_SECRET_KEY`, and `STRIPE_PRICE_PRO` / `STRIPE_PRICE_ENTERPRISE` (Stripe Price IDs).
2. Register a webhook at `{APP_BASE_URL}/api/webhooks/stripe`; set `STRIPE_WEBHOOK_SECRET`.

Checkout + customer portal are then live from **Settings**.

## 8. Meeting capture (Recall.ai)

Without a key, the built-in **simulator** streams a realistic call (great for demos). For
real Google Meet / Zoom / Teams:
1. `RECALL_API_KEY` (+ `RECALL_REGION`, e.g. `us-east-1`).
2. Expose `{APP_BASE_URL}/api/webhooks/recall` publicly (Recall posts transcripts there).
3. On the dashboard, paste a meeting link → **Send copilot to meeting**.

## 9. Database & migrations

- **SQLite (default):** zero config; tables auto-create. Good for pilot.
- **PostgreSQL (production):** set `DATABASE_URL=postgresql+psycopg://user:pass@host:5432/db`
  and run migrations:
  ```bash
  ./scripts/migrate.sh          # docker: alembic upgrade head in the backend container
  # or manual:  cd backend && alembic upgrade head
  ```
  With Docker you can run a bundled Postgres: `docker compose --profile full up -d`.

## 10. Deploy & operations (VM)

```bash
git clone <repo> cue && cd cue
cp .env.example .env            # set keys + your domain URLs
./scripts/setup.sh              # first-time: build, start, health-check, migrate
```

Day-2:

| Task | Command |
|---|---|
| Redeploy (after `git pull`) | `./scripts/deploy.sh` |
| Restart (after editing `.env`) | `./scripts/restart.sh` |
| Migrate (Postgres) | `./scripts/migrate.sh` |
| Logs | `./scripts/logs.sh [backend\|frontend]` |
| Stop (keep data) | `./scripts/stop.sh` |

Containers use `restart: unless-stopped` (survive reboots). Put a reverse proxy
(Caddy/Nginx) in front for TLS + your domain, then set the `*_URL` vars to the public
HTTPS addresses and redeploy. Details + rollback/backup: **[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)**.

## 12. Troubleshooting

| Symptom | Fix |
|---|---|
| **Port already in use** | Another app holds 3000/8000 — set `FRONTEND_PORT` / `BACKEND_PORT` in `.env`. |
| **OAuth fails / redirect error** | Redirect URI must exactly match `{APP_BASE_URL}/api/connectors/{provider}/callback`; HTTPS in prod; client id/secret set. |
| **Blank page after a build** | Don't run `next build` while `next dev` is running (shared `.next`). Stop dev, then build. |
| **402 on start meeting / connect** | Plan limit reached — upgrade on **Settings** (dev mode applies instantly). |
| **Postgres: tables missing** | Run `./scripts/migrate.sh` (SQLite auto-creates; Postgres needs migrations). |
| **Connector "demo" instead of real OAuth** | Set that provider's `*_CLIENT_ID/_SECRET`; restart. |
| **Docker daemon not running** | Start Docker Desktop / `colima start`, then re-run `./scripts/setup.sh`. |
